# GreenLight – проектный промт

## 1. Общее описание

GreenLight – умный светильник на ESP32 с управлением через мобильное приложение и MQTT-сервер.  
Цели: локальное управление без интернета и облачное управление через аккаунт и MQTT.

## 2. Сервер и домен

- IP сервера: `45.150.9.50`
- Домен: `https://greenlight-lamp.ru/`
- Сервисы:
  - Mosquitto MQTT over TLS: порт `8883`, строгая проверка TLS, работает с устройством по `mqttDeviceId`, `mqttUsername`, `mqttPassword`.
  - FastAPI Auth API: `http://45.150.9.50:8000`
    - План: позже повесить за Nginx, чтобы API было по `https://greenlight-lamp.ru/auth/...`.
  - ISPmanager: панель управления, следит за Nginx, ufw и сертификатами.

Firewall (ufw):

- Открыты порты: 80/tcp, 443, 22/tcp, 53, 8883/tcp, 8000/tcp.

## 3. ESP32 / прошивка

- Плата: ESP32.
- Светильник работает в двух режимах:
  - AUTO – яркость по расписанию.
  - MANUAL – пользователь вручную включает/выключает и меняет яркость.

### HTTP API (локальное управление)

Устройство поднимает точку доступа (AP) и HTTP-сервер на `192.168.4.1` порт 80.

- `GET /status` – возвращает строку `ON|OFF currentBrightness mode connectivityStatus`.
- `GET /info` – JSON с информацией о прошивке, `mqttDeviceId`, продукте.
- `GET /schedule` – возвращает строки расписания (до 8 интервалов) в формате `enabled,startHour,...,fadeMinutes` по строке на интервал.
- `POST /schedule` – применяет расписание, требует параметр `key == authSecret`.
- `POST /command` – команды:
  - `ON`, `OFF`
  - `BRIGHT:xx`
  - `MODEAUTO`, `MODEMANUAL`
  - тоже с `key == authSecret`.
- `POST /wifi` – приём домашнего Wi‑Fi (ssid + password + key). Сохраняет в NVS, подключается к роутеру и запускает NTP.

### Идентификаторы и безопасность

- `authSecret`:
  - Генерируется при первом запуске (случайный HEX).
  - Хранится в NVS.
  - Печатается в QR‑коде и используется как `key` для HTTP.
- MQTT:
  - `mqttDeviceId` – основан на MAC‑адресе STA.
  - `mqttUsername` и `mqttPassword` – генерируются устройством и хранятся в NVS.
  - Темы: `lamp/<mqttDeviceId>/status`, `.../command`, `.../schedule`.

## 4. Мобильное приложение (Flutter)

Основные файлы:

- `lib/main.dart` – запускает `GreenLightApp` с `WelcomeScreen`.
- `lib/screens/welcome_screen.dart` – стартовый экран:
  - Кнопка **«Войти в аккаунт»** – позже будет вести на экран логина.
  - Кнопка **«Создать аккаунт»** – ведёт на экран регистрации (`AuthRegisterScreen`).
  - Кнопка **«Продолжить без аккаунта»** – ведёт на `DevicesScreen` для локального управления.
- `lib/screens/devices_screen.dart` – список локальных устройств, переход к управлению лампой.
- `lib/screens/lamp_control_screen.dart` – управление яркостью, режимами.
- `lib/screens/lamp_schedule_screen.dart` – редактирование расписания; при сохранении сразу отправляет `POST /schedule` на ESP32.
- `lib/screens/qr_scanner_screen.dart` – сканирование QR точки доступа лампы.
- `lib/screens/auth_register_screen.dart` – экран регистрации по email:
  - Поля: email, пароль, галочка согласия на обработку ПД.
  - Запрос: `POST http://45.150.9.50:8000/auth/register` с JSON `{email, password, consent}`.

### Потоки использования

#### Без аккаунта

1. Пользователь запускает приложение → `WelcomeScreen`.
2. Жмёт «Продолжить без аккаунта».
3. Переходит на `DevicesScreen`, сканирует QR светильника, подключается к `192.168.4.1`.
4. Управляет лампой локально (яркость, расписание), интернет не нужен.

#### С аккаунтом (регистрация и облако)

1. На `WelcomeScreen` жмёт «Создать аккаунт» → открывается `AuthRegisterScreen`.
2. Вводит email + пароль + ставит галочку.
3. Приложение вызывает `/auth/register` на FastAPI.
4. Сервер создаёт пользователя, генерирует код подтверждения, логирует отправку письма (пока заглушка).
5. Пользователь вводит код на экране подтверждения (будет `AuthVerifyScreen`).
6. Сервер подтверждает email, отдаёт токен.
7. После логина появляется экран «Мои светильники», где можно:
   - добавить лампу по QR с `mqttDeviceId` и `authSecret`;
   - настроить домашний Wi‑Fi лампы;
   - управлять лампой удалённо по MQTT.

## 5. Правила работы с ассистентом (Prompty)

1. Работаем неспеша, по одному блоку команд:
   - сначала обсуждаем идею шагом,
   - потом даём конкретный набор команд или целый файл.

2. Если правка большая – ассистент даёт целый файл (например, `welcome_screen.dart` или `auth_register_screen.dart`), чтобы можно было сделать:
   - `notepad lib\screens\file.dart`,
   - `Ctrl+A → вставить → сохранить`.

3. Ассистент не придумывает новые файлы и имена, пока это не согласовано.  
   Всегда опирается на структуру репозитория `greenlight_app` на GitHub.

4. Перед изменениями ассистент:
   - сверяется с текущим кодом на GitHub,
   - сверяется с прошивкой ESP32,
   - учитывает этот документ `docs/project_prompt.md` как источник правил.

5. Утренний старт работы:
   - я даю:
     1. ссылку на репозиторий (`https://github.com/BeriBanyu/greenlight_app`),
     2. актуальный файл прошивки ESP32 (`ver1.ino` или аналог),
     3. ссылку на этот промт (`docs/project_prompt.md`),
   - ассистент читает всё и дальше действует по описанным правилам.

